# The Python 3.12 dependency set production and CI are known to work under.
#
# A pip constraint file, not a requirements file: it says which version of a
# package may be installed, never that it must be installed. So the same file
# serves the production install, which asks for the package alone, and the CI
# install, which asks for the package and its dev extra -- production does not
# acquire pytest or ruff by being handed a file that pins them.
#
# WHY IT EXISTS
# -------------
#
# Every production run builds a fresh virtual environment, and until this file
# existed each one re-resolved the whole tree against whatever PyPI had that
# morning. The floors in pyproject.toml are deliberately floors -- they say
# what the code needs, which is a different question from what production is
# known to work under -- so a run could pick up a numpy, pandas, scipy or shap
# released hours earlier and no reviewed decision anywhere said it should. The
# frozen Gate 3 artifacts are unpickled by scikit-learn, the priced parquet is
# written by pyarrow and the distributions go through numpy: a silent minor
# bump in any of them is a change to what production serves.
#
# HOW IT WAS PRODUCED
# -------------------
#
# From the versions successful production and CI runs actually resolved, not
# from "latest". Every line below is a version that has already served a slate
# or passed the suite. The transitive section is the closure pip resolves from
# the direct section: it is pinned too, because an unpinned transitive package
# is the same daily drift one level down, and `pip install -c` only constrains
# what it names.
#
# A dependency added to pyproject.toml must be added here with the version the
# run that proved it resolved. `python -m pip install --dry-run --report` over
# this file reports any package the resolver reached that is not named here,
# and tests/test_dependency_reproducibility.py fails when one exists.
